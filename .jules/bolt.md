## 2025-03-05 - [Canvas Resizing in requestAnimationFrame loop]
**Learning:** In a fast `requestAnimationFrame` loop (like QR scanning `tick()`), unconditionally updating `canvas.width` and `canvas.height` with calculated dimensions directly triggers continuous browser backing store reallocation, severe garbage collection pressure, and loss of 2D context. Furthermore, using floating point values (from dividing dimensions) causes the internal integer representation to never match, forcing an update every frame even if the source video dimensions haven't changed.
**Action:** Always cache canvas dimensions. Before checking for updates, ensure the calculated new dimensions are integers (using `Math.floor()`). Only assign new values to `canvas.width` and `canvas.height` if they differ from the current values.

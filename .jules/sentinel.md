## 2026-06-17 - [Add missing setSafeHTML function to prevent XSS]
 **Vulnerability:** The application was calling `setSafeHTML` in two places (`index.html` lines 771 and 1114) when rendering AI responses, but the function itself was never actually defined in the code. Because of this, when AI responses were returned, they triggered a `ReferenceError` resulting in failed rendering, bypassing the XSS mitigation that was apparently intended to be there but incompletely applied in a previous commit.
 **Learning:** Sometimes an intended security control (like a safe HTML wrapper) is added to call sites but the actual implementation is accidentally omitted or removed during refactors, leaving the functionality broken.
 **Prevention:** Ensure utility functions used for security mitigations are actually defined and correctly implemented, and test them with automated code reviews and unit tests where possible.

# 旧Webスキャナーの保管

2026-10-04。Wi-Fi・Discord版への刷新で、QR/BLEを使うWebスキャナーを運用から外すための保管。終了案内は別ブランチで準備し、新版の実機受入が済むまでmainの公開は切り替えない。

- 元のコード: main `7c42c29e73c67c41340e5f18dc707a768aa9bc23` の直下index.html。
- 保管先: [index.html.txt](index.html.txt)。Windowsの作業コピーから元の53,095バイトを変更せず保存した。改行変換を無効にして保管する。テキスト拡張子で保管し、通常の公開入口から旧アプリへ誘導しない。
- SHA256: `f521a78c66fdbaf4cbc59db74862c78f0114a4c8de60ebc54b765c5de8181588`。
- 元のGit blob（LF改行、51,608バイト）: `bbab73d7b236cf0d83987f8ced07a9f7721ff523`。保管したWindowsコピーのGit blob（CRLF改行、53,095バイト）: `902bf292b33436e0e292d0dfe12ae26ecbb8a16c`。コードの内容は同じで、改行形式を区別する。
- Jestテストと過去のベンチマークは、この保管HTMLを読み込む。Jestの通過は旧Webのカメラ・BLE・外部APIの実動作を保証しない。

## コードを戻す方法

新しい作業ブランチを作り、index.html.txtの内容をリポジトリ直下index.htmlへコピーする。Jestの読み込み先を直下へ戻し、表示・端末互換性・権限・通信を確認してからPRを作る。履歴を戻す操作やmainへの強制更新は不要。

これはWebコードの復元方法。マイコンの旧版への書き換えや再公開は別の判断となる。[旧版の課題](../../ISSUES.md)、[刷新仕様](../../docs/REDESIGN.md)、[設計判断](../../docs/DECISIONS.md)を先に確認する。旧版の不具合が修正済みになったわけではない。

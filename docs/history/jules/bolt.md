## 2026-06-02 - [Canvas Render Overhead in requestAnimationFrame]
**Learning:** In a `requestAnimationFrame` loop, unconditionally assigning `canvas.width` and `canvas.height` forces the browser to reallocate the backing store and reset the 2D context *even if the values haven't changed*. This causes a significant performance bottleneck, especially on mobile devices scanning QR codes. Also, when calculating dimensions based on aspect ratio, the result must be explicitly cast to an integer (e.g., using `Math.floor()`); otherwise, floating-point precision issues can cause the dimensions to always appear "changed" compared to the canvas's internal integer dimensions, leading to continuous resets.
**Action:** When working with Canvas inside rendering loops, always cache the source dimensions (`videoWidth`, `videoHeight`). Only recalculate the target canvas size when the source changes, ensure the calculated target dimensions are integers, and conditionally update the canvas properties (`if (canvas.width !== targetWidth) canvas.width = targetWidth;`) to avoid unnecessary and costly browser repaints/reallocations.

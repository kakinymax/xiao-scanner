# 0時のグラフと毎時の温度監視

2026-10-04、本人の指示で通知を見直したwifi-discord-1.1.0の仕様。判断の経緯はDECISIONS.mdのD016。1.0.1の実機受入とは分けて記録する。

## 通知先と内容

- 既存Webhookのチャンネル：日本時間0時に、前日の00:00〜24:00の温度・湿度グラフをPNGで1回送信。上が温度、下が湿度。日中の定期数値報告と通常起動報告は廃止。
- 追加Webhookのチャンネル：温度の初回超過・新しい温度帯への悪化・正常復帰、センサー取得不能と復帰。湿度の異常通知は行わず、グラフには残す。
- 初回の時刻付き測定を確認した後、毎時（日本時間の各正時）に直近の測定で監視。欠測を温度の復帰と扱わない。再起動しても同じ時間の判定を繰り返さない。

## 温度の通知例

高温は40℃を超えたら異常、40℃以下で復帰。低温は0℃未満で異常、0℃以上で復帰。各境界はUSB設定ツールから変更可能。

| 毎時の確認値 | 通知 | 次の高温通知境界 |
|---|---|---|
| 40.0℃ | なし | 初回の40℃超を待つ |
| 40.5℃ | 初回の高温 | 41℃以上 |
| 40.5℃が2〜3時間続く | なし | 41℃以上のまま |
| 41.0℃ | 悪化 | 42℃以上 |
| 40.5℃、続いて41.9℃ | なし | 42℃以上のまま |
| 42.8℃ | 悪化（途中の帯ごとの連投なし） | 43℃以上 |
| 40.0℃以下 | 正常復帰 | 初回の40℃超へ戻る |

低温側は対称で、−0.5℃を通知したら次は−1℃以下、−1℃台なら次は−2℃以下。0℃以上へ復帰するまで境界を戻さない。

本体の測定は30秒、グラフの点は12分間隔・最大120点。Discordの毎時監視とは独立。本体ブザーは測定ごとの条件が120秒続いたときに3回鳴り、継続中は60分間隔。温度が正常範囲へ戻ったことも120秒確認して止める。画面・グラフ・期間切替・履歴の電源断保持は継続。

## 保存と通信

0時の送信対象を、現在のローリング履歴とは別に確定して保存。遅れて送る際にも対象期間を動かさない。初回導入当日の過去分は自動送信せず、次の0時から開始。複数日の通信断では最新の前日へまとめ、欠測は空白またはNO DATA。電源断やセンサー欠測を線でつながない。

毎時の確認時間・異常状態・通知境界・未送信イベントと、グラフの対象/成功日・確定履歴をthermo_dailyのCRC付き二重保存へ保持。HTTP200を受けたものを成功として保存。同じ起動中の成功分は保存再試行中も繰り返さない。成功直後から保存までの間に電源が切れた場合や、Discord受理後の応答が失われた場合の完全な重複排除までは保証しない。

既存のthermo_cfg、thermo_hist、LittleFS、アプリ領域の配置は保持。1.0.1のWi-Fi・既存Webhook・画面/測定/保存条件を引き継ぎ、通知条件だけ40℃超/0℃未満・湿度通知停止・定期数値停止・ブザー60分へ移行。追加のWebhookはPCで非表示入力。状態確認はURL・SSID・パスワードを返さない。

HTTPSと画像作成は既存の別タスク。640×400・1bit PNGとmultipartを1つの最大34,516バイトの作業領域で生成し、送信後に解放。TLS証明書検証、リダイレクト禁止、HTTP200の確認、429の待ち時間、通信失敗時の間隔を維持。グラフと異常を直列に送り、Discordが指定した待ち時間は両方へ反映。無効なWebhookで止まる送信先と他の正常な送信先は分ける。

## USB設定ツール

新版のメニュー7で追加の異常・復帰用Webhookだけを保存する。既存URLやWi-Fiの再入力は不要。メニュー4は異常用チャンネルへの手動送信、6はグラフ用チャンネルへの直近24時間の試験画像。どちらも自動の日次送信や温度の通知境界を完了扱いにしない。秘密値をチャット・設定ファイル・コマンド引数へ入れない。

# 新しいWi-Fi・Discord温湿度計の使い方

現在の通知仕様はwifi-discord-1.1.1の[0時グラフ・毎時監視](DAILY_TREND.md)。日中の数値報告・通常起動報告は廃止し、既存チャンネルへ前日のグラフ、追加チャンネルへ40℃超/0℃未満の温度悪化・復帰を送る。以下の1.0.xの通知説明・受入記録は変更前の履歴として読む。

XIAO ESP32C3・Grove AHT20・XIAO拡張ボードをそのまま使う。USBなどで常時給電し、本体で温度・湿度と履歴グラフを表示する。通知はWi-FiからDiscordへ直接送る。スマホスキャナー、QR、BLE、不快指数、AI予測・学習用大量ログは新しいスケッチに含まれない。

コードは[mcu_firmware/xiao_env_wifi_discord](../mcu_firmware/xiao_env_wifi_discord/README.md)。旧スケッチ・モデル・計測ログは保管されている。**PCでの検証と、実際に本体を書き換えて使えることの確認は別**。[検証記録](WIFI_DISCORD_VALIDATION.md)と[共同対応票](WIFI_DISCORD_JOINT_ACTIONS.md)で状態を確認する。

## Discordの送信先を用意する

PCのDiscordで、自分が管理するサーバーを開く。サーバーはテキストチャンネルをまとめる場所で、通知はそこで選んだチャンネルへ届く。

1. 自分のサーバーがなければ、左側の「＋」から「自分で作成」を選び、名前を付けて作成する。既存の自分のサーバーを使ってもよい。[公式のサーバー作成手順](https://support.discord.com/hc/ja/articles/204849977)。
2. サーバー名のメニューから「サーバー設定」を開き、「連携サービス」へ進む。
3. 「ウェブフックを作成」を押し、名前を「温度計」など分かる名前にして、通知を受けるテキストチャンネルを選ぶ。
4. 変更した内容を保存し、「ウェブフックURLをコピー」でURLを取得する。[公式のWebhook作成手順](https://support.discord.com/hc/ja/articles/228383668)。
5. コピーしたURLをそのまま、下記のPC設定ツールのWebhook欄へ入力する。URLは送信に使う秘密情報なので、チャット・PR・公開文書へ貼らない。

ここまでの作成手順の確認は、ユーザーのDiscordアカウントで実際に作成・受信できたことの確認とは別。作成メニューが見つからない場合は、そこで表示されている項目名をCodexへ伝える。

## この実機でのセットアップ順

本体はPCのUSBとベースへ同時に接続できないと、本人が確認した。**XIAO単体をPCへつないだまま接続設定を終え、最後にベースとAHT20へ戻して受入を行う。** セットアップの途中でベースへ戻すことを要求しない。

PC接続中はUSBの新版応答、設定保存、Wi-Fi、NTPの時刻、Discordへの試験メッセージを確認する。センサーがないため、温湿度は取得できず、その旨のメッセージが届く場合がある。これは温湿度の実測値が送信できたことの確認ではない。

最後にPCから外して、XIAOをベースとAHT20へ接続する。温湿度と履歴グラフ、ボタンとブザー、実測値の通知、電源断と保存復元、センサー/通信の切断と復帰を確認する。詳しい分担と状態は[共同対応票](WIFI_DISCORD_JOINT_ACTIONS.md)に残す。

## 初めて使うとき

1. Codexと一緒に、現在の実機の追加ログを保全してから新しいコードへ切り替える。書き込み前に本体と保存データ・パーティション構成を確認する。スケッチのコンパイルだけでは本体は変わらない。
2. 本体とPCをUSBで接続し、[PC設定ツール](../tools/setup_temperature.py)を開く。メニュー「1」で、2.4GHz Wi-Fiの名前・パスワードと、DiscordのWebhook URLを入力する。パスワードとURLの入力は表示しない。秘密値をこのチャットやGitHubへ書く必要はない。
3. 数十秒後に「3: 状態確認」でWi-Fi、ネット時刻、温湿度、保存状態を確認する。「4: Discordへ1回送信して確認」で受信を確かめる。起動・設定後にも自動で1回報告する。

このWindows環境では、Codexが準備済みPythonから設定ツールを直接開く。PowerShellの起動時にPSReadLineの発行元確認が表示されたため、そのウィンドウは閉じて直接起動へ変更した。実行ポリシーや発行元の信頼設定は変更していない。

通常のPowerShellが使用できる環境では、リポジトリのフォルダから次のコマンドでも設定ツールを開ける。

```powershell
.\tools\setup_temperature.ps1
```

ポートが複数あれば接続したXIAOの番号を選ぶ。別のPCではPythonとpyserial 3.5を用意し、`python tools/setup_temperature.py`で開く。ツールはWi-Fi版かを確認してから接続設定を送る。旧版に設定を送ったり、ファームウェアを書き込んだりするツールではない。USBの設定操作中も本体は計測を続ける。

## 本体の操作

- **短押し**: 現在値 → 温度グラフ → 湿度グラフ → 現在値。ブザーが鳴っていれば停止する。
- **1秒以上押して離す**: グラフの期間を24時間 → 12時間 → 6時間の順で切り替える。現在値画面なら温度グラフへ移る。
- **消灯時の短押し**: 画面を表示する。次の短押しから画面を切り替える。
- 長く押しても履歴や接続設定を消去しない。BOOT/RESETは画面操作用ではない。

画面のTは温度、Hは湿度。OFFはWi-Fi未接続。NTPはネット時刻、RTCは本体時計、WAITは時刻待ち。温湿度の取得に失敗した場合は古い値を現在値として表示せず、Sensor unavailableと表示する。通信できない間も計測と本体表示を続ける。

## 初期設定と変更

下記は運用を始めるための初期値で、健康・安全基準を保証するものではない。PCメニュー「2」で変更できる。画面常時表示と定期通知の間隔はユーザーへ確認した提案値で、未回答時はこの値を使う。

| 項目 | 初期値 |
|---|---|
| 計測 | 30秒ごと |
| グラフ | 12分間隔、最大120点。24/12/6時間表示 |
| 履歴保存 | 12分ごとに保存。変更は1〜120分 |
| 定期通知 | 30分ごと。0分を設定すると定期報告を停止 |
| 高温 | 30℃以上が2分続いた場合 |
| 高湿度 | 80%以上が2分続いた場合 |
| 正常復帰 | 温度29℃以下・湿度75%以下の状態がそれぞれ2分続くと該当項目を回復とする |
| 同じ異常の再通知 | 30分間隔 |
| ブザー | 高温・高湿度の成立時と30分ごとの継続確認で、150msの音を3回 |
| 画面 | 常時表示。ボタン時だけの設定では30秒で消灯 |
| センサーエラー | 取得失敗が2分続いた場合に通知。正常な取得が2分続くと回復通知 |

通知には本体名、理由、温度・湿度、測定日時と通知日時を日本語で載せる。高温・高湿度の判定は個別に停止できる。設定を保存すると異常の継続時間を判定し直し、設定後の報告を送る。

## 通信できないとき

接続は20秒で区切り、15秒から最大5分の間隔で再試行する。HTTPSの待ちは別の処理で行い、本体の計測・ボタンを止めない。時刻がまだなければDiscord送信を待つ。ネット時刻を取得した後は、電池付きRTCと本体時計を通信できない間の時計として使う。

通信中に起きた状態変化は最新の状態にまとめる。定期報告を何十件もためて復帰時に一斉送信しない。その間の詳細な変化すべてをDiscordへ後送する設計ではない。本体のグラフは別に記録を続ける。

Discordから待ち時間を指示された場合、その時間を守る。接続失敗等は1回の試行の後15秒・30秒で再試行し、3回失敗したら少なくとも15分待つ。401/403/404や内容エラーでは自動送信を止め、設定確認を求める。設定変更でも指示された待ち時間を飛ばさない。ネットの応答が失われた場合は再送が重複する可能性があり、厳密な1回だけの配送保証ではない。

状態確認の「送信成功」はDiscordから確認応答を受けたこと。「送信を開始」は成功の確認前なので、状態とDiscord側の実際の受信を確認する。

## 履歴と接続設定の保存

グラフの各点に日時と区切りを保存する。再起動・センサー応答なし・大きな時刻修正の前後を、連続測定したように線でつながない。時刻未確定中の測定値は表示するが、日時を作り上げて履歴に追加しない。

履歴はCRC付きの二つの保存枠に交互に書き、起動時に有効な新しい枠を選ぶ。電源断では直近の未保存分が失われることがある。保存失敗時は要確認と表示し、再試行する。旧版の履歴を新版へ自動で読み込む機能はない。旧領域・ログはこのスケッチから初期化しない。

Wi-FiとWebhookの設定は本体に保存し、PCには設定ファイルを作らない。標準NVSは暗号化を保証するものではない。メニュー「5」は**新版の接続設定だけ**を消し、温湿度の履歴や表示設定を保持する。ソースコードには本物の接続情報を入れない。

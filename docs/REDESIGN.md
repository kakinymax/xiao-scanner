# Wi-Fi・Discord温湿度計への刷新仕様

2026-10-04。コード変更前にユーザーが指定した機能範囲。[設計判断](DECISIONS.md)と[ヒストリー](PROJECT_HISTORY.md)を先に残した。前半は当初の計画、末尾は実装結果。現在は新版コードを実機へ書き込み、RESET後のUSB起動を確認済みで、ベース/センサーと実通信の受入を進めている。[実機切替の記録](DEVICE_WIFI_CUTOVER.md)を参照。

## 構成と残すもの

温湿度センサー → XIAO ESP32C3で計測・表示・履歴・ブザー → Wi-Fi → Discord Webhookで通知。

- USBなどで常時給電する。
- 温度・湿度の計測、本体の現在値表示、温度・湿度の履歴グラフを残す。
- 本体のブザーを残す。条件・頻度はこれから定める。
- グラフの履歴保存は残す方針。既存の保存手法を参考に、新版で保存・復元を確認する。
- 定期通知・イベント通知と、Wi-Fi接続・再接続、ネット経由の時刻合わせを実装する。既存RTCを通信できない間の時計として使う案。

## 新版で廃止する機能

| 対象 | 扱い |
|---|---|
| Webスキャナー全体 | 再開発しない。GitHub URLからブラウザで開く旧アプリを運用対象から外す |
| QR生成・転送・Export画面 | 新版から廃止 |
| BLEによる時刻合わせ・ログ取得 | 新版から廃止。スマホとの直接通信を日常操作に要求しない |
| 不快指数の表示・グラフ・判定 | 廃止。旧DI依存のブザー条件はそのまま使わない |
| 本体のAI温度予測 | ユーザー指定により廃止。model.hは保管 |
| AI学習用の毎分・約1か月ログ | ユーザー指定により廃止。グラフ用の履歴は残す |
| 旧全ログ消去の長押し操作 | 廃止。ボタン操作を温湿度画面・グラフに合わせて再構成 |
| 旧WebのGemini利用・CSV出力 | 旧Webとともに運用対象から外す |
| 電池のためのディープスリープ中心の動作 | 常時給電の計測・通信に合わせて変更。画面の消灯は別に決める |

「新版で使わない」という決定と、「旧資料・コードを削除した」という実施結果は別。旧データ・モデル・ソース・Git履歴・実機バックアップは保管する。

## 履歴保存の再利用

保存ソースでは、グラフは12分間隔の120点をPreferencesへ保存し、AI学習用の大量ログはLittleFSへ保存する別の処理。AIログを廃止しながらグラフの保存は残せる。

旧保存はAIの120回カウントに連動する約2時間ごととボタン起動時。突然の電源断で直近の未保存分が失われ得る。新版では保存周期を独立させ、不快指数の配列を外す。各点の時刻と電源断中の空白を扱い、古い値を詰めて連続測定だったように表示しない。保存成功・復元・再起動後の表示を確認する。

保存方式を再利用することと、現在の実機にある旧履歴を新版へ移すことは別。旧履歴の移行は未確定。領域変更・書き込み・消去の前に追加されたデータを保全する。

## 実装前に定める項目

1. 計測間隔、グラフの表示期間、履歴の保存周期。旧版の24/12/6時間表示を引き継ぐ案。
2. Discordの定期通知間隔、イベントの条件、正常復帰通知、同じ状態の再通知間隔。
3. ブザーの鳴る条件・時間・繰り返し、本体画面を常時表示するかボタンで表示するか。
4. 初回のWi-Fi・Webhook設定方法。PC/USBで設定する案。秘密の実値を公開Gitやログへ入れない。

## 通信と検証の方針

計測・履歴・表示を通信待ちで長時間止めない。再接続・再送の回数と待ち時間を制限し、通信復帰時に古い定期報告を大量に送らない。HTTPSの証明書を検証する。Discordの送信結果と制限応答を扱う。測定日時・通知理由・温度・湿度を日本語で表示する。

旧AIログの位置ずれ、旧Webの最適な版の追跡、旧ソースと実機の完全一致は、新版開発の必須工程から外す。調査結果は保管し、「修正済み」ではなく「新版では機能廃止のため対象外」と区別する。再利用する表示・計測・保存処理の問題は新版の検証対象。
